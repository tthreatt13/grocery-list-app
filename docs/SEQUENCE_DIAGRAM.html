Key Components Interaction

sequenceDiagram participant User participant Dashboard as Dashboard Page participant UrgentItems as UrgentActionItems participant Suggestions as SmartSuggestions participant Insights as InsightsDisplay participant API as API Client participant Backend as FastAPI Backend User->>Dashboard: Load dashboard Dashboard->>API: getGroceryListsWithItems() Dashboard->>API: getDashboardInsights() API->>Backend: GET /api/grocery-lists API->>Backend: GET /api/dashboard/insights Backend-->>API: Return data API-->>Dashboard: Return transformed data Dashboard->>UrgentItems: Pass urgent items Dashboard->>Suggestions: Pass suggestions Dashboard->>Insights: Pass stats UrgentItems-->>User: Display urgent items Suggestions-->>User: Display suggestions Insights-->>User: Display statistics User->>UrgentItems: Click "Add to List" UrgentItems->>API: addGroceryItem() API->>Backend: POST /api/grocery-lists/{id}/items Backend-->>API: Return created item API-->>UrgentItems: Return item UrgentItems-->>User: Show success, update UI User->>Suggestions: Click "Accept" on suggestion Suggestions->>API: createGroceryList() or addGroceryItem() API->>Backend: POST request Backend-->>API: Return created resource API-->>Suggestions: Return data Suggestions-->>User: Show success, dismiss suggestion

Notes

  • Authentication: All API requests (except webhooks) require a valid Clerk JWT token in the Authorization header
  • Error Handling: Frontend implements optimistic updates with rollback on error for better UX
  • Caching: Weather forecasts are cached in the backend to reduce API calls
  • Permissions: Backend validates user permissions (household membership, admin roles) for all operations
  • Data Transformation: Frontend uses adapter pattern to transform API responses to UI-friendly formats
  • Session Storage: Dismissed items and suggestions are stored in browser sessionStorage for the current session
